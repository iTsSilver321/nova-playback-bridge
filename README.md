# NOVA playback bridge

An independently authored, ad-free torrent-to-HLS server for NOVA. It retrieves an explicitly selected torrent file and converts requested 16-second batches to H.264/AAC, with 480p/720p/1080p choices bounded by the source resolution. The complete VOD timeline supports forward/backward seeking. Audio streams can be selected independently. Viewers use HTTPS video on iOS, Android, Windows, macOS and Linux without installing a torrent engine.

NOVA's authenticated Worker creates private sessions with a server-only shared secret. The bridge accepts hashes and file indices rather than arbitrary URLs. Access uses expiring random capability links. Local range reads are exposed only on a separate loopback listener. Queued conversions, viewer/session limits, disk checks, timeouts, idle cleanup and a private-address torrent peer blocklist bound resource use. Links may be shared with a watch party, so possession of a playback URL grants playback until expiration. Never publish NOVA_BRIDGE_KEY or log playback paths.

This server does not supply movie licenses, peers, translations or an exhaustive catalog. Use media you have permission to stream. Torrent availability and the host's resources still determine whether a source plays. The software is free and contains no advertising. Hosting has separate resource policies: Render's free plan sleeps, shares compute, has monthly transfer limits, and may suspend high-volume outbound traffic. It cannot provide unlimited public streaming. No paid plan is configured.

## Deploy

The isolated repository is generated by `node scripts/export-bridge.mjs` from NOVA's source. Its Dockerfile installs FFmpeg and the exact Node dependencies. The service binds `0.0.0.0:$PORT`. Runtime settings:

| Variable | Purpose |
| --- | --- |
| NOVA_BRIDGE_KEY | At least 32 random characters; the same value is stored privately in NOVA's Worker. |
| NOVA_ALLOWED_ORIGINS | Comma-separated HTTPS NOVA origins. |
| NOVA_BRIDGE_CACHE_GB | Disk budget; default 20 GB, free deployment 5 GB. |
| NOVA_BRIDGE_JOBS | Concurrent converter jobs; free deployment 1. |
| NOVA_BRIDGE_SESSIONS | Concurrent sessions; free deployment 2. |
| NOVA_BRIDGE_CACHE | Cache directory, default `.nova-bridge-cache`; Docker `/cache`. |
| NOVA_FFMPEG | Optional FFmpeg executable override. |

Set `NOVA_BRIDGE_URL` to the service's returned HTTPS origin and `NOVA_BRIDGE_KEY` through Sites runtime environment settings. `/api/playback` in NOVA reports configuration and readiness. New sessions require ChatGPT sign-in and respect the profile PIN. Per-account requests are atomically limited in D1.

The HLS capability links expire after six hours; idle sessions expire after twenty minutes. A sleeping/restarted host loses transient cache and sessions, so reopen the source. Cloud libraries remain in NOVA's separate database. Hardware decoding, AirPlay and casting depend on browser/receiver support. Conversion on a small free instance can buffer on demanding files.

## Verification and provenance

`npm run test:bridge` in NOVA generates a new HEVC/MKV test video with two audio streams, seeds it through a real TCP torrent client, then verifies random-seek segments, H.264/AAC conversion, qualities, language selection, rejected unauthorized/origin requests and link expiration. Browser verification is separate from these checks. Dependencies retain their own licenses: [WebTorrent](https://github.com/webtorrent/webtorrent), [FFmpeg](https://ffmpeg.org/legal.html), [ffmpeg-static](https://github.com/eugeneware/ffmpeg-static). The Docker FFmpeg build includes GPL components; its upstream source and license notices remain available in the Debian package distribution.
